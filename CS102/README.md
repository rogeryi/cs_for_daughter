# CS102: 现代 C/C++ 编程与复杂软件系统入门
*Modern C/C++ Programming and Software Systems*

---

## 课程定位

CS102 是 CS101 之后的一年制核心课程。它不再只是一门“C++ 面向对象编程”课程，而是通过现代 C++ 编程，把数据结构、系统概念、并发基础和复杂软件设计的核心思想融入同一条学习主线。

课程的核心问题是：

> 一个程序从“能运行的小脚本”，如何成长为“结构清晰、资源可靠、能被分析和维护的软件系统”？

## 学习目标

完成本课程后，学生应能够：

1. 使用现代 C++ 编写结构清晰的小型程序
2. 理解值、引用、指针、地址、栈、堆和对象生命周期
3. 优先使用标准库容器和算法，而不是手写复杂基础设施
4. 根据问题选择合适的 `std` 容器，并理解其基本性能特征
5. 使用 RAII 和智能指针管理资源生命周期
6. 理解文件、进程、线程、同步等系统概念如何映射到编程 API
7. 理解复杂软件中的模块、接口、依赖方向、事件系统和资源系统
8. 具备阅读中大型开源项目核心设计的入门能力，尤其是游戏引擎类项目
9. 使用 Xcode 调试器观察变量、对象生命周期、调用栈、线程状态和简单内存现象

## 教学原则

1. **标准库优先**
   先学会正确使用 `std::vector`、`std::string`、`std::unordered_map`、`std::jthread`，再解释它们背后的数据结构和系统概念。

2. **底层概念嵌入语言机制**
   内存地址跟着指针讲，地址空间跟着程序运行讲，数据结构跟着容器讲，线程同步跟着 `std::mutex` 和 `std::condition_variable` 讲。

3. **不追求大学低年级全量覆盖**
   不单独实现红黑树、哈希表、操作系统内核或调度器。高中兴趣阶段的重点是理解概念、会使用 API、能分析真实软件。

4. **软件系统设计贯穿后半程**
   每个复杂主题都连接到“软件为什么这样组织”：生命周期、所有权、模块边界、接口、依赖方向、事件和资源管理。

5. **游戏引擎作为长期参照物**
   使用 Godot 的 Node、SceneTree、Signal、Resource 等设计作为案例，但不要求完整编译或通读 Godot 源码。

6. **调试器是一等教学工具**
   CS102 不只讲“代码应该如何运行”，还要让学生在 Xcode 中通过断点、单步执行、变量面板、调用栈和线程视图观察程序真实运行状态。

7. **C 作为引擎边界语言**
   C 的比例围绕 Godot/游戏引擎中常见的底层接口来安排：C 字符串、数组、指针、头文件、链接、ABI 直觉、第三方库边界和 GDExtension 的 C API。

8. **一对一现场结对学习**
   课程按教师和学生共同面对同一个工程的方式设计。教师讲解、追问、示范调试；学生现场修改代码、运行、观察、解释现象。课程不依赖小组讨论或课后大量作业，而依赖课堂中的即时反馈。

## 每周授课运行流程

CS102 的每次课程都以一个独立的周目录和 Xcode IDE 工程为载体。

1. **课前创建目录**
   授课前，根据已有目录确定下一周编号，例如 `week03`。我负责在 `CS102/week03/` 下创建本周学习目录。

2. **创建空 Xcode 工程**
   我在本周目录下创建一个可以被 Xcode IDE 打开的空 C++ 工程。工程作为学生本周编辑、运行、调试代码的主入口。

3. **代码进入工程**
   学生可以直接在 Xcode 中写代码，也可以通过和我对话生成代码。我负责协助把新增 `.cpp`、`.h`、资源文件或示例文件加入工程结构。

4. **学生在 Xcode 中观察程序**
   学生主要在 Xcode IDE 中运行、设置断点、单步执行、查看变量、观察调用栈、查看线程状态和理解内存现象。

5. **命令行作为观察窗口**
   当需要观察编译命令、目标文件、可执行文件、符号、链接过程或其他编译产物时，学生可以要求我调用命令行构建/检查，并由我报告结果。

这个流程的目标是让“写代码”和“观察程序运行”发生在同一个可视化环境中。命令行不作为日常主入口，而是作为理解工具链和编译产物的辅助方式。

## 一对一课堂节奏

每节 2 小时建议按现场互动来组织：

1. **共同打开工程，5-10 分钟**
   确认本周目录、Xcode 工程、上一节遗留代码和今天要观察的问题。

2. **概念引入，15-25 分钟**
   教师用少量图示、类比和已有 Python 经验解释今天的新概念。

3. **教师示范，20-30 分钟**
   教师现场写一小段代码，并边写边解释为什么这样组织。

4. **学生接手，30-40 分钟**
   学生在 Xcode 中修改、补全或扩展代码。教师通过追问确认她是否理解。

5. **调试观察，25-35 分钟**
   设置断点、单步执行、查看变量、调用栈、内存布局或线程状态，把抽象概念变成可见现象。

6. **AI 辅助创作，10-20 分钟**
   学生提出一个小扩展，我协助生成或改造代码，并把代码加入当前工程。

7. **口头复盘与报告提示，5-10 分钟**
   学生用自己的话解释本节课最重要的概念，教师记录学习报告要点。

### Xcode 可视化观察主线

| 抽象概念 | Xcode 中的观察方式 |
|---------|-------------------|
| 控制流 | 断点、Step Over、Step Into |
| 函数调用 | 调用栈 |
| 变量状态 | 变量面板、Watch 表达式 |
| 内存布局 | 地址打印、变量面板、Memory Graph、lldb |
| 对象生命周期 | 构造/析构断点、调用栈、Memory Graph |
| lambda / 闭包 | 捕获变量、闭包对象状态、算法调用栈 |
| 线程 | Debug Navigator、线程列表、线程调用栈 |
| 同步等待 | 条件变量断点、线程暂停状态 |
