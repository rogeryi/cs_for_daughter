## 教师导读

这一节的目标不是追求写很多代码，而是建立 CS102 的学习方式：每周一个目录、一个 Xcode 工程，学生在 IDE 中写代码、运行、调试、观察。她需要从第一节课就明白：C++ 不是 Python 那种“写一行解释一行”的体验，而是“源代码 -> 编译 -> 链接 -> 可执行文件 -> 运行时观察”。

本节课最重要的三个概念：

1. `main()` 是 C++ 程序入口
2. C++ 程序运行前需要编译
3. Xcode 调试器可以把程序运行过程停下来观察

学生常见卡点：

- 以为 Xcode 左侧很多文件都必须理解
- 分不清源代码、工程、可执行程序
- 看到 `std::cout`、`#include`、`;` 会觉得“语法很吓人”
- 不知道断点停住后应该看哪里

讲解策略：先让她成功运行，再解释“刚才发生了什么”。不要先讲太多编译理论。

## 一、从 Python 到 C++

### 1. Python 的运行体验

在 CS101 中，学生写过这样的 Python：

```python
name = "Amos"
print(f"Hello, {name}!")
```

Python 的体验是：

```text
源代码 -> Python 解释器 -> 运行结果
```

学生通常不需要关心生成了什么可执行文件。

### 2. C++ 的运行体验

C++ 更接近这样的流程：

```text
main.cpp
  -> 编译器
  -> 目标文件
  -> 链接器
  -> 可执行文件
  -> 运行
```

第一节课只需要知道：

- C++ 代码要先被工具处理
- Xcode 帮我们调用编译器和链接器
- Run 按钮背后不只是“解释一行代码”

现场追问：

- “Python 文件和 C++ 文件都叫源代码，它们运行前有什么不同？”
- “Xcode 点 Run 的时候，可能做了哪几件事？”
- “如果你改了代码但没有重新运行，会看到新结果吗？”

## 二、第一个 C++ 程序

### 教师示范代码

在 `main.cpp` 中输入：

```cpp
#include <iostream>

int main() {
    std::cout << "Hello, C++!" << std::endl;
    return 0;
}
```

### 逐行讲解

```cpp
#include <iostream>
```

意思是：我要使用标准输入输出库。`iostream` 里有 `std::cout`。

```cpp
int main() {
```

`main` 是程序入口。程序开始运行时，会从这里进入。

`int` 表示这个函数最后会返回一个整数。现在先记住：`return 0` 通常表示程序正常结束。

```cpp
std::cout << "Hello, C++!" << std::endl;
```

`std::cout` 表示标准输出，通常就是 Xcode 控制台。

`<<` 可以暂时理解为“把右边的内容送到左边的输出流中”。

`std::endl` 表示换行并刷新输出。

```cpp
return 0;
```

告诉操作系统：程序正常结束。

### 和 Python 对比

| Python | C++ |
|--------|-----|
| `print("Hello")` | `std::cout << "Hello" << std::endl;` |
| 没有显式入口也能运行脚本 | `main()` 是明确入口 |
| 通常不写分号 | 大多数语句以 `;` 结束 |
| 类型常由运行时决定 | 类型在编译期非常重要 |

## 三、学生接手练习

让学生修改程序：

```cpp
#include <iostream>

int main() {
    std::cout << "欢迎来到 CS102!" << std::endl;
    std::cout << "今天我们开始学习 C++。" << std::endl;
    std::cout << "我会用 Xcode 观察程序如何运行。" << std::endl;
    return 0;
}
```

学生操作：

1. 修改字符串内容
2. 点击 Run
3. 在控制台查看输出
4. 故意删掉一个分号，观察编译错误
5. 恢复分号，再次运行

教师解释编译错误时要强调：

- 编译器不是在“责备你”，它是在告诉你哪里不符合语法
- C++ 错误信息一开始会显得长，但我们先学会看第一条关键错误

现场追问：

- “如果删掉分号，程序是运行时才错，还是运行前就错？”
- “控制台显示的是源代码，还是程序运行后的输出？”
- “你能指出哪一行是真正让文字显示出来的吗？”

## 四、加入变量

### 教师示范代码

```cpp
#include <iostream>
#include <string>

int main() {
    std::string playerName {"Mira"};
    int level {1};

    std::cout << "玩家：" << playerName << std::endl;
    std::cout << "等级：" << level << std::endl;

    return 0;
}
```

### 本节只讲必要概念

这段代码引入了两个变量：

- `std::string playerName {"Mira"};`
- `int level {1};`

暂时不展开所有类型细节，只告诉学生：

- C++ 创建变量时要写类型
- `{}` 是现代 C++ 推荐的初始化写法之一
- `std::string` 需要 `#include <string>`

## 五、Xcode 调试观察

### 观察目标

让学生看到程序不是“一下子神秘地跑完”，而是一行一行执行。

### 操作步骤

1. 在 `std::string playerName {"Mira"};` 左侧点击，设置断点
2. 点击 Run
3. 程序停在断点处
4. 查看底部或左侧变量面板
5. 使用 Step Over 逐行执行
6. 观察 `playerName` 和 `level` 何时出现
7. 打开 Debug Navigator，查看调用栈

### 讲解要点

断点的意义：

```text
请程序运行到这里先停下来，让我看看现场发生了什么。
```

Step Over 的意义：

```text
执行当前这一行，然后停在下一行。
```

调用栈的意义：

```text
程序是怎么走到这里的。
```

第一节课只需要看到 `main()` 在调用栈里即可，不需要解释复杂栈帧。

现场追问：

- “断点停住时，这一行执行了吗？”
- “Step Over 之后，变量面板发生了什么变化？”
- “调用栈里看到 `main`，说明了什么？”

## 八、常见错误与讲解

### 1. 忘记分号

错误：

```cpp
std::cout << "Hello" << std::endl
```

解释：C++ 大多数语句用分号结束。分号像一句话的句号。

### 2. 忘记 `#include <string>`

错误：

```cpp
std::string name {"Mira"};
```

但没有包含 `<string>`。

解释：C++ 需要明确告诉编译器使用哪些库。

### 3. 把中文标点写进代码语法位置

错误示例：

```cpp
int level {1}；
```

解释：字符串里可以有中文，但代码符号要使用英文半角符号。

### 4. 害怕错误信息

讲解方式：先只看第一条错误和红色标记，不要求一次读懂全部输出。
