# Week 24: 进程、线程、`thread` 和 `jthread`

## 课程信息

| 项目 | 内容 |
|------|------|
| **所属部分** | CS102B：标准库、并发与软件系统设计 |
| **关键词** | 进程、线程、`std::thread`、`std::jthread`、并发 |
| **系统连接** | 一个程序中可以有多条执行线 |

## 学习目标

1. 区分进程和线程的基本概念
2. 创建和等待 `std::thread`
3. 使用 `std::jthread` 简化线程生命周期
4. 理解并发不等于自动变快
5. 使用 Xcode 线程视图观察不同线程的调用栈

## 核心概念

- 进程是运行中的程序实例
- 线程是进程中的执行线
- `join` 表示等待线程结束
- `jthread` 析构时会自动 join，并支持停止请求

## 课堂实践

- 创建一个后台加载任务
- 主线程显示进度提示
- 对比忘记 join 的风险和 `jthread` 的便利

## Xcode 调试观察

- 在主线程和后台线程中分别设置断点
- 打开 Debug Navigator 查看当前线程列表
- 切换线程并观察每条线程的调用栈
- 讨论“同一个进程中有多条执行线”如何在调试器中变得可见

## 系统/设计连接

游戏引擎和工具软件经常把资源加载、日志、网络、编辑器任务放到后台。但并发会引入共享状态和生命周期问题。
