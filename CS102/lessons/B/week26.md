# Week 26: 数据竞争、死锁和线程安全队列

## 课程信息

| 项目 | 内容 |
|------|------|
| **所属部分** | CS102B：标准库、并发与软件系统设计 |
| **关键词** | 数据竞争、死锁、线程安全队列、生产者消费者 |
| **系统连接** | 并发错误常常不是每次都出现 |

## 学习目标

1. 理解数据竞争的基本含义
2. 理解死锁的直觉
3. 实现一个简化线程安全队列
4. 学会用设计减少共享状态
5. 使用 Xcode 观察并发错误的非确定性和线程暂停位置

## 核心概念

- 数据竞争来自多个线程同时访问同一数据且至少一个写入
- 死锁常来自多个锁的等待循环
- 线程安全队列是任务系统的常见基础
- 最好的同步有时是减少共享

## 课堂实践

- 制造一次数据竞争并观察不稳定结果
- 讨论两个锁交叉等待如何造成死锁
- 实现 `push`、`try_pop`、`wait_pop` 的简化队列

## Xcode 调试观察

- 在两个线程写入同一变量的位置设置断点
- 多次运行并比较不同执行顺序
- 发生死锁示例时，查看每个线程停在哪个锁附近
- 在线程安全队列中观察生产者和消费者的调用栈

## 系统/设计连接

复杂软件中，并发设计应该尽量让数据所有权清晰。任务队列比随意共享变量更容易推理。
