# CS102 课程规格说明

---

## 课程名称

**CS102: 现代 C/C++ 编程与复杂软件系统入门**
*Modern C/C++ Programming and Software Systems*

---

## 必须满足的需求

### 目录与文档

1. `CS102/README.md` 必须作为课程入口文档
2. `CS102/doc/design.md` 必须描述课程设计思想和取舍
3. `CS102/doc/spec.md` 必须描述课程规格和验收标准
4. `CS102/doc/plan.md` 必须描述课程开发和维护计划
5. `CS102/lessons/A` 必须包含上半部分课程内容
6. `CS102/lessons/B` 必须包含下半部分课程内容

### 课程结构

1. 课程总长度为 30 节课
2. 每节课按 2 小时设计
3. 授课形式为一对一现场授课
4. 上半部分 A 包含第 1-15 节课
5. 下半部分 B 包含第 16-30 节课
6. 每节课都应包含：
   - 课程信息
   - 学习目标
   - 核心概念
   - 教师示范
   - 课堂实践
   - 学生现场操作
   - Xcode 调试观察
   - 系统或设计连接
   - 现场追问
   - 学习报告提示

### 一对一授课模式

1. 每节课应围绕当前周的 Xcode 工程进行
2. 教师负责解释概念、示范代码、提出追问和引导调试观察
3. 学生负责现场编辑、运行、调试、观察和口头解释现象
4. 课程应避免依赖小组活动
5. 课程不以大量课后作业为核心，而以课堂中的即时反馈和学习报告为核心
6. 每节课应包含至少 3 个现场追问，用于检查学生是否真正理解
7. 每节课应保留 AI 辅助创作环节，让学生把基础概念应用到有趣的小扩展中

### 开发环境

1. 主开发环境必须是 Xcode IDE
2. 每次课程前应创建独立周目录，例如 `CS102/week03/`
3. 每个周目录下应包含一个可由 Xcode IDE 打开的空 C++ 工程
4. Xcode 工程是学生编辑、运行、调试和观察程序的主入口
5. 学生可以直接在 Xcode 中写代码，也可以通过 AI 生成代码后加入工程
6. AI 应协助把新增 `.cpp`、`.h`、资源文件或示例文件加入本周工程
7. 命令行不作为日常主入口，但可以用于观察编译产物、目标文件、可执行文件、符号和链接过程
8. 学生必须学习：
   - 创建和运行 Xcode C++ 工程
   - 设置断点
   - 单步执行
   - 查看变量
   - 查看调用栈
   - 查看线程状态和线程调用栈
   - 观察对象关系和简单内存布局
   - 阅读基础编译错误和运行时错误
9. 命令行、CMake 和 lldb 作为辅助工具出现，用于理解开源项目构建、底层工具链和编译产物

### 语言与标准

1. 主语言为 C++23
2. 辅助语言为 C23
3. 应优先教授现代 C++ 标准库机制
4. 应避免把裸指针、裸数组、手动 `new/delete` 作为常规写法
5. 必须教授 RAII、智能指针、标准容器和标准算法
6. C 的内容应围绕 Godot/游戏引擎接口边界设计，包括 C 字符串、数组、指针、头文件、链接、ABI 直觉、第三方库和 GDExtension C API

### 数据结构融入方式

数据结构不作为独立课程出现，而是随标准库容器学习：

| 数据结构概念 | 教学载体 |
|-------------|----------|
| 动态数组 | `std::vector` |
| 固定数组 | `std::array` |
| 连续视图 | `std::span` |
| 双端队列 | `std::deque` |
| 链表 | `std::list`，重点讲使用场景和局限 |
| 有序树 | `std::map` / `std::set` |
| 哈希表 | `std::unordered_map` / `std::unordered_set` |
| 栈和队列 | `std::stack` / `std::queue` |
| 堆和优先队列 | `std::priority_queue` |
| 图 | 邻接表和游戏地图示例 |

### 操作系统概念融入方式

操作系统不作为独立课程出现，而是随 API 和程序行为学习：

| 系统概念 | 教学载体 |
|---------|----------|
| 地址和地址空间 | 指针、引用、对象地址 |
| 栈和堆 | 局部对象、动态对象、智能指针 |
| 编译和链接 | 头文件、源文件、CMake |
| 文件系统 | `std::filesystem` |
| 时间 | `std::chrono` |
| 线程 | `std::thread` / `std::jthread` |
| 同步 | `std::mutex` / `std::condition_variable` |
| 数据竞争 | 共享状态和线程安全队列 |
| 进程 | 概念讲解和命令行观察，不作为主要编程 API |
| 调试器 | Xcode 断点、变量面板、调用栈、线程视图 |
| 内存布局 | Xcode 变量观察、Memory Graph、地址打印、lldb 辅助观察 |
| 闭包 | lambda 捕获列表、调试器中的闭包对象、捕获值和引用的区别 |

### 软件系统设计

课程必须覆盖以下设计概念：

1. 模块边界
2. 接口与实现
3. 依赖方向
4. 生命周期管理
5. 资源管理
6. 事件系统
7. 组合优先于复杂继承
8. 源码分析方法
9. Godot 的 Node、SceneTree、Signal、Resource 案例

## 项目要求

### 上半部分项目

上半部分项目应是一个命令行小型系统，建议方向：

- 命令行背包和资源管理器
- 简单 roguelike 房间探索
- 文本战斗模拟器
- 小型素材索引工具

项目必须使用：

- 多文件结构
- `std::vector`
- `std::string`
- 至少一个自定义类
- RAII 或智能指针中的至少一种思想
- 基础错误处理

### 下半部分项目

下半部分项目应围绕“mini scene tree / 小型 2D 游戏框架”展开。

项目必须体现：

- Node 树结构
- update 生命周期
- 简单事件或 signal 机制
- 资源表或资源加载器
- 至少一种标准库关联容器
- 至少一个并发或任务队列概念的简化实现
- 一份源码分析报告

## 验收标准

课程初版满足以下条件即视为可进入逐节扩写阶段：

1. `README.md` 能说明课程定位、目标、结构和原则
2. `doc/design.md` 能说明为什么这样设计
3. `doc/spec.md` 能说明课程必须覆盖什么
4. `doc/plan.md` 能说明如何继续细化课程
5. `lessons/A` 中存在第 1-15 节课文件
6. `lessons/B` 中存在第 16-30 节课文件
7. 每个 lesson 文件都有统一基本结构
8. 课程内容与“不单独教授数据结构和操作系统，而是嵌入 C++ API”的目标一致
9. 课程内容明确把 Xcode IDE 调试作为核心学习方式
10. 关键抽象概念应设计可视化观察任务，包括内存布局、调用栈、线程状态和 lambda 捕获
11. 课程运行流程明确支持“周目录 + Xcode 工程 + IDE 调试 + 命令行产物观察”
12. 课程内容应符合一对一现场授课模式，包含教师示范、学生操作、现场追问和口头复盘
