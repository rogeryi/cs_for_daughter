## 一、本周课程核心知识点

### 分而治之

一个RPG包含角色、剧情、战斗、道具、存档、界面等问题。先确定每个问题
输入什么、改变什么、返回什么，再把相应函数和类放到模块里。
例如购买输入玩家和物品名称，检查金币、修改背包，返回成功状态和提示。

### 高内聚与低耦合

高内聚：战斗伤害、护盾、敌人反击放在战斗模块中。
低耦合：战斗模块不需要知道鼠标坐标、字体大小和存档路径。
换一张头像不应改变伤害计算；修改药水价格不应修改绘图函数。

旧图形版VisualGame包揽剧情、战斗和存档，虽然项目有许多文件，
实际运行时仍绕过了早期战斗模块。这说明“文件多”不自动等于模块化。

### RPG核心组件与类

Character保存角色共有属性和受伤、恢复行为；Player继承它，
增加能量、装备、金币、经验。Companion封装队友技能。
GameSession记录一整局游戏，Encounter记录一场战斗，
VisualGame处理界面输入和显示。

```python
from story import GameSession
from combat import Encounter

session = GameSession()
session.complete()          # 教学示例：序章完成
session.choose(0)           # 城门选择先救人
battle = Encounter(session, 0)
battle.act("attack")        # 处理一个回合
print(battle.enemy.hp)
```

对象传递意味着战斗与会话使用同一个玩家，生命值变化会回到城镇状态栏。
不要复制一个互不关联的玩家，否则会出现“战斗受伤、回城却没受伤”的问题。

### 游戏循环

图形版每帧接收事件，提交按钮动作，更新游戏状态和音乐，再绘制画面。
命令行循环等待一次输入；图形界面必须持续刷新，所以Encounter一次只处理
一个动作，不能在点击后进入等待input()的阻塞循环。

```python
while self.running:
    for event in pygame.event.get():
        self.handle_event(event)
    self.update_music()
    self.draw()
    self.clock.tick(FPS)
```

## 二、游戏开发扩展知识

- 状态机：title、create、hub、dialog、choice、battle等状态决定可用操作。
- dataclass：为GameSession生成初始化方法；default_factory保证不同游戏不共享列表。
- property：attack_power由基础攻击与已装备武器计算，避免保存两份互相矛盾的数值。
- 逐回合模型：战斗接受字符串动作，返回胜利、失败、撤退或继续，方便测试。
- Boss阶段门槛：伤害跨越阈值时停在下一阶段起点，让玩家有机会应对机制。

这些扩展服务于本周的架构目标，不要求现在掌握复杂引擎设计。
