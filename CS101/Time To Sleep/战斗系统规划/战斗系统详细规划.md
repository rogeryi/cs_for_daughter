# 《Time To Sleep》战斗系统规划

> **文档类型：** 战斗系统详细设计文档  
> **参考游戏：** 《空洞骑士》（操作/战斗节奏）、《女神异闻录4》（2D动画风格）  
> **开发引擎：** Pygame Zero  
> **游戏类型：** 类银河恶魔城 2D 横版动作游戏  

---

## 一、核心战斗设计理念

### 1.1 设计原则

1. **高难度但公平：** 类似《空洞骑士》，敌人攻击有明确预警，死亡是学习过程
2. **节奏控制：** 战斗→探索→解密→Boss，张弛有度
3. **能力驱动：** 新能力解锁新战斗方式，鼓励玩家尝试不同策略
4. **叙事结合：** Boss 战是叙事高潮，战斗机制反映角色背景

### 1.2 参考游戏分析

| 参考游戏 | 借鉴要素 | 适配方案 |
|---------|---------|---------|
| **空洞骑士** | 下劈、冲刺无敌帧、护符系统 | 改为配件系统，赛博朋克化命名 |
| **空洞骑士** | Boss 多阶段、攻击预警 | 保留，加入塔的世界观背景 |
| **P4** | 2.5头身角色、流畅动画 | 像素风+高清混合，32×48像素主角 |
| **空洞骑士** | 长椅存档点、地图探索 | 保留，改为塔的休息点 |

## 二、核心操作设计

### 2.1 基础操作表

| 操作 | 按键 | 功能 | 冷却/限制 |
|------|------|------|----------|
| **移动** | A/D 或 ←/→ | 左右移动，支持加速度和减速 | 无 |
| **跳跃** | Space | 可变跳跃高度（短按小跳，长按大跳） | 无 |
| **攻击** | J 或 Z | 近战攻击，支持连击（最多 3 段） | 攻击后摇 |
| **下劈** | ↓ + J（空中） | 向下攻击，可踩在敌人头上 | 无 |
| **冲刺** | K 或 X | 短距离快速位移，有无敌帧 | 0.5 秒 |
| **闪避** | L 或 C | 翻滚闪避，短暂无敌 | 0.8 秒 |
| **治疗** | E | 恢复生命值，需要站立不动 | 治疗次数限制 |
| **特殊技能** | Q | 消耗能量释放技能 | 能量限制 |

### 2.2 操作优先级

```
最高优先级：治疗 > 闪避 > 冲刺 > 攻击 > 移动 > 跳跃
```

**说明：**
- 治疗时不可移动/攻击，但可被闪避/冲刺打断
- 闪避/冲刺无敌帧期间不可攻击
- 攻击后摇期间不可闪避/冲刺

## 三、战斗机制详解

### 3.1 攻击系统

#### 3.1.1 连击系统
- **第1段：** 快速前斩（伤害 5，前摇 3 帧，攻击 2 帧，后摇 7 帧）
- **第2段：** 横斩（伤害 7，前摇 4 帧，攻击 3 帧，后摇 8 帧）
- **第3段：** 上挑（伤害 10，前摇 6 帧，攻击 4 帧，后摇 10 帧，击飞敌人）

**连击窗口：** 每段攻击后摇结束前 5 帧内按下攻击键可触发下一段

#### 3.1.2 蓄力攻击
- **蓄力时间：** 0.5 秒（小蓄力）/ 1 秒（大蓄力）
- **小蓄力：** 伤害 15，范围 1.5 倍
- **大蓄力：** 伤害 25，范围 2 倍，击退敌人

#### 3.1.3 下劈机制
- **触发条件：** 空中 + ↓ + J
- **伤害：** 8（对敌人）/ 0（对地面）
- **特殊效果：**
  - 踩在敌人头上可再次跳跃（类似空洞骑士）
  - 对空中敌人造成双倍伤害
  - 可破坏特定地面

### 3.2 防御系统

#### 3.2.1 冲刺无敌帧
- **持续时间：** 0.3 秒
- **移动距离：** 150 像素
- **冷却时间：** 0.5 秒
- **视觉效果：** 残影效果，屏幕轻微震动

#### 3.2.2 闪避无敌帧
- **持续时间：** 0.4 秒
- **移动距离：** 100 像素（翻滚）
- **冷却时间：** 0.8 秒
- **视觉效果：** 翻滚动画，尘土效果

#### 3.2.3 硬直系统
- **受击硬直：** 0.5 秒（不可操作）
- **击退距离：** 根据敌人攻击类型（30-80 像素）
- **无敌帧：** 受击后 0.2 秒（防止连续受击）

### 3.3 治疗系统

- **治疗次数：** 初始 2 次，最大 4 次
- **治疗量：** 每次恢复 33% 最大生命值
- **治疗时间：** 1.5 秒（站立不动）
- **打断条件：** 受击、移动、攻击
- **配件加成：**
  - **快速凝聚模块：** 治疗时间缩短 30%
  - **移动聚焦单元：** 治疗时可移动

## 四、装备系统（原护符系统）

### 4.1 装备槽位

- **武器槽位：** 1 个（主武器）
- **配件槽位：** 3-5 个（初始 3 个，探索解锁至 5 个）
- **装备点数：** 每个配件消耗 1-4 点，总点数限制（初始 9 点，最大 15 点）
- **切换限制：** 仅在休息点/存档点可更换，战斗中不可更换

### 4.2 武器系统

## 五、敌人设计

### 5.1 敌人分类

| 类型 | 特征 | 示例 | 应对策略 |
|------|------|------|---------|
| **巡逻型** | 固定路线，速度慢 | 废弃物机器人、安保机器人 | 观察路线，绕后攻击 |
| **伏击型** | 隐藏在墙壁/地面 | 黏菌生物、基因改造猎手 | 注意环境提示，保持距离 |
| **追击型** | 发现玩家后冲锋 | 融合者狂战士、齿轮守卫 | 利用闪避/冲刺躲避 |
| **远程型** | 发射投射物 | 无人机、狙击无人机 | 利用掩体，近身攻击 |
| **重甲型** | 高防御，需要破甲 | 监工、富人保镖 | 下劈破甲，蓄力攻击 |

### 5.2 敌人 AI 设计

#### 5.2.1 状态机

```
[待机] → [巡逻] → [发现玩家] → [追击] → [攻击] → [硬直] → [待机]
```

#### 5.2.2 感知系统

- **视觉感知：** 扇形区域，距离 200 像素
- **听觉感知：** 圆形区域，距离 100 像素（玩家攻击/跑步触发）
- **配件影响：** 系统入侵工具可降低感知范围 30%

#### 5.2.3 攻击预警

- **视觉提示：** 攻击前 0.5 秒显示红色预警区域
- **声音提示：** 攻击前有独特音效
- **动画提示：** 敌人攻击前有明显前摇动画

## 六、Boss 战设计

### 6.1 Boss 战通用机制

1. **多阶段设计：** 每个 Boss 至少 3 个阶段
2. **阶段转换：** HP 降至 66%、33% 时触发
3. **检查点：** Boss 战前自动存档
4. **奖励：** 能力解锁 + 配件 + 剧情揭示

## 七、战斗关卡流程

### 7.1 单区域标准流程

```
[到达新区域] 
    ↓
[安全区/休息点] ←───────┐
    ↓                    │
[接取支线任务]            │
    ↓                    │
[探索敌方区域]            │
    ↓                    │
[战斗 + 解密]            │
    ↓                    │
[收集信息/线索]          │
    ↓                    │
[NPC对话/世界观揭示]     │
    ↓                    │
[Boss战]                │
    ↓                    │
[获得能力/奖励] ─────────┘
    ↓
[前往下一个区域]
```

### 7.2 节奏设计

| 阶段 | 时长 | 节奏 | 情感 |
|------|------|------|------|
| **安全区** | 5-10 分钟 | 放松 | 好奇/希望 |
| **探索** | 15-20 分钟 | 中等 | 紧张/好奇 |
| **战斗** | 10-15 分钟 | 紧张 | 恐惧/专注 |
| **解密** | 5-10 分钟 | 思考 | 疑惑/理解 |
| **Boss** | 5-10 分钟 | 高潮 | 震撼/胜利 |
| **返回** | 5-10 分钟 | 释放 | 悲伤/希望 |

## 八、技术实现规划

### 8.1 Pygame Zero 技术栈

#### 8.1.1 核心模块

| 模块 | 功能 | Pygame Zero API |
|------|------|----------------|
| **玩家控制** | 移动/跳跃/攻击 | `keyboard`, `update()`, `draw()` |
| **碰撞检测** | 平台/敌人/投射物 | `Rect.colliderect()` |
| **动画系统** | 角色/敌人动画 | `Actor`, `draw()` |
| **状态机** | 玩家/敌人状态 | 自定义状态机 |
| **配件系统** | 装备/效果 | 自定义数据结构 |
| **Boss AI** | 多阶段/攻击模式 | 自定义 AI 系统 |

#### 8.1.2 性能优化

- **对象池：** 投射物/粒子效果使用对象池
- **碰撞优化：** 空间分割（四叉树）
- **动画优化：** 预加载动画帧，使用精灵表
- **内存管理：** 区域切换时释放未使用资源

## 九、待解决问题

### 9.1 技术挑战

1. **Pygame Zero 性能限制：** 大量敌人/投射物时的帧率下降
   - **解决方案：** 对象池 + 空间分割

2. **碰撞检测精度：** 平台跳跃需要精确碰撞
   - **解决方案：** 使用 `Rect` + 自定义碰撞逻辑

3. **动画流畅度：** 2.5 头身角色需要流畅动画
   - **解决方案：** 精灵表 + 预加载

### 9.2 设计挑战

1. **难度平衡：** 高难度但公平，避免玩家挫败
   - **解决方案：** 明确攻击预警，多次测试调整

2. **装备平衡：** 14 种配件需要平衡
   - **解决方案：** 点数限制 + 组合策略

3. **Boss 战节奏：** 多阶段需要保持紧张感
   - **解决方案：** 阶段转换动画 + 音乐变化
